Candidates for what to add next
------------------------------------------------------------------
Checked against what this machine's Ubuntu actually ships (a real
cross-gcc AND a qemu-user target - the same feasibility check m68k's own
plan_toolchain_dispatcher-adjacent research did), not guessed:

- s390x (IBM Z/zSeries) - the most interesting candidate. 64-bit,
  big-endian, a genuinely different CISC ISA (rich addressing modes,
  condition codes) - would exercise more of the design space than another
  RISC clone. gcc-s390x-linux-gnu + qemu-s390x both real.
- HPPA (PA-RISC) - 32-bit, big-endian RISC with real oddities (space
  registers, no branch delay slot the usual way). Retro-interesting,
  technically straightforward. gcc-hppa-linux-gnu + qemu-hppa both real.
- ppc64le - lowest-effort of the three: extends the *existing* ppc.ml
  infrastructure to a 64-bit little-endian sibling, the same way amd64/
  arm64/riscv64 were grown from their 32-bit relatives, rather than a
  from-scratch ISA. gcc-powerpc64le-linux-gnu + qemu-ppc64le both real.
  (Big-endian ppc64 has no Debian/Ubuntu package at all anymore - only the
  LE variant - so that's the only realistic PowerPC64 option.)

Checked and NOT a good fit, worth recording so it isn't re-litigated:
anything with a fundamentally different word size than this IR assumes
(8-bit targets like 6502/Z80, or GPU-style SIMD ISAs) would need surgery
to the compiler's own type/width assumptions, not just a new arch/
directory - a different category of effort than everything done so far.

Other qemu-user targets on this machine with no matching Debian cross-gcc
found (so not immediately actionable without more toolchain work):
LoongArch (loongarch64/loong64 - a genuinely modern, growing ISA, worth
revisiting if Debian ever packages a cross-gcc for it), SuperH (sh4), ARC,
Xtensa, MicroBlaze, OpenRISC (or1k), Nios II, Hexagon, CRIS.
